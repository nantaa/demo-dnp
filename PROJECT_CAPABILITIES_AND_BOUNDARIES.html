✓ FITUR BEROPERASI ALUR OPERASIONAL

Manajemen Kanban 16 Tahap Berurutan

Mengontrol siklus berkas riksa uji secara ketat dari Tahap 1 (PO/SPK/Proposal) sampai Tahap 16 (Selesai). Berpindahnya kartu antar-tahap wajib memenuhi dokumen prasyarat yang terverifikasi. Dilengkapi alur penolakan berjenjang (*Rejection Cascade*) jika berkas dinyatakan perlu perbaikan.

16 Tahap Verifikasi Prasyarat Riwayat Audit Lengkap
✓ FITUR BEROPERASI KEAMANAN & PRIVASI

Akses Khusus Tim RU dengan Proteksi Nilai Finansial

Menyediakan hak akses penuh untuk personel teknis (*Tim Riksa Uji / Inspektur*). Secara otomatis menyembunyikan (*masking*) seluruh data nilai komersial (harga penawaran, nilai PO, nominal invoice, faktur pajak). Personel lapangan fokus pada aspek teknis keselamatan dan penyusunan LHPP tanpa melihat angka keuangan.

Tim RU / Tim Riksa Uji Privasi Harga Terjaga Kerahasiaan Bisnis
✓ FITUR BEROPERASI ANTARMUKA DOKUMEN

Modal Preview Dokumen Pop-up Teratas

Memungkinkan peninjauan langsung file PDF dan gambar tanpa perlu mengunduh ke komputer lokal. Jendela tinjau (*Preview Modal*) menggunakan lapisan paling atas (z-[9999]) sehingga tidak terpotong oleh panel samping, lengkap dengan tombol perbesar/perkecil (*zoom*) dan unduh cepat.

Tinjau Langsung (PDF & Gambar) Lapisan Teratas Tanpa Terpotong Fitur Zoom In/Out
✓ FITUR BEROPERASI EFISIENSI KEUANGAN

Unggah Tagihan Satu Pintu di Tahap 10

Menyederhanakan pengunggahan dokumen penagihan menjadi 1 slot terpadu: "Invoice, Kwitansi & Faktur Pajak". Tim Keuangan cukup mengunggah 1 file bundel tagihan untuk memenuhi syarat lolos Tahap 10 tanpa harus mengunggah file tiga kali secara terpisah.

Tahap 10 Invoice, Kwitansi & Faktur Pajak 1 Kali Unggah Selesai
✓ FITUR BEROPERASI AUDIT PEMBAYARAN

Kalkulasi Otomatis PPN 11% & Kunci Pengiriman SUKET

Menghitung nilai PPN 11% secara otomatis sesuai regulasi pajak yang berlaku. Pada Tahap 14 (*Verifikasi Bayar*), berkas dikunci secara ketat dan tidak dapat dipindahkan ke Tahap 15 (*Kirim SUKET ke Klien*) sebelum status pembayaran terverifikasi Lunas oleh tim Keuangan.

PPN 11% Otomatis Kunci Keamanan Tahap 14 Cegah SUKET Keluar Sebelum Lunas
✓ FITUR BEROPERASI NOTIFIKASI OTOMATIS

Pengiriman Laporan Harian via Email (Daily Digest)

Menjalankan perintah terjadwal untuk mengirimkan ringkasan operasional pagi ke email pimpinan dan koordinator: memuat rekap antrean pekerjaan aktif, peringatan batas waktu Disnaker (H-5), tagihan jatuh tempo, dan pembayaran yang menunggu verifikasi.

Laporan Harian Email Peringatan Batas Waktu SLA Rekap Eksekutif Otomatis
✓ FITUR BEROPERASI KECERDASAN PENJADWALAN

Mesin Rekomendasi Penugasan Inspektur

Mencocokkan jenis alat uji (Boiler, Crane, Lift, Instalasi Petir) dengan sertifikat kompetensi SKP personel yang masih berlaku. Menghitung beban kerja aktif setiap personel dan memberikan peringatan jika inspektur telah melebihi batas kuota tugas serentak (standar: 5 pekerjaan berjalan).

Pencocokan Sertifikat SKP Batas Beban Kerja Tugas Cegah Kelelahan Personel
✕ BELUM TERSEDIA BUKAN FUNGSI HR

Belum Ada Pencatatan Absensi & Kehadiran Personel

Pemberitahuan: DNP Monitor adalah sistem pelacakan alur kerja dokumen riksa uji, bukan sistem HRIS (Human Resource Information System). Sistem ini belum menyediakan fitur presensi jam kerja harian, absen *clock-in / clock-out*, pencatatan lembur, maupun manajemen cuti karyawan.

Bukan Sistem Absensi Tidak Ada Presensi Harian Bukan Modul Penggajian
✕ BELUM TERSEDIA BUKAN FUNGSI EVALUASI HR

Belum Ada Penilaian Kinerja Karyawan (Performance Review / KPI)

Sistem belum menyediakan modul evaluasi penilaian kinerja individu berkala (*performance appraisal*), formulir penilaian kompetensi tahunan, atau perhitungan rapor KPI karyawan. Sistem hanya mencatat status riwayat pekerjaan teknis (selesai, tertunda, atau revisi) untuk keperluan pelacakan berkas klien.

Belum Ada KPI Individu Bukan Performance Review HR Fokus pada Berkas Pekerjaan
✕ BATASAN TEKNIS STABILITAS PRODUKSI

Pembaruan Eksperimental "v3" (20 Tahap) Tidak Digunakan

Mengapa Versi 3 Ditinggalkan: Cabang eksperimental v3 yang memecah alur menjadi 20 tahap menyebabkan beban administrasi berlebih di lapangan, menimbulkan siklus ketergantungan kode yang tidak stabil, dan memperumit alur kerja teknisi. Sistem produksi secara resmi dikunci pada **alur 16 tahap stabil** di cabang utama (*main*).

v3 Tidak Dipakai Bukan 20 Tahap Terkunci di 16 Tahap Stabil
✕ BATASAN EKSTERNAL REGULASI PEMERINTAH

Tidak Terhubung API Langsung ke Server Disnaker / Kemnaker

Layanan dinas ketenagakerjaan pemerintah daerah (Disnaker) dan Kementerian Ketenagakerjaan RI tidak menyediakan antarmuka pertukaran data otomatis (*Public Web API*). Oleh karena itu, pencatatan status pengesahan Suket pada Tahap 8 menggunakan nomor tanda terima fisik dan pembaruan tanggal manual oleh admin.

Tidak Ada API Disnaker Bukan Sinkronisasi Kemnaker Pencatatan Tanda Terima Manual
✕ BATASAN OPERASIONAL TRANSAKSI PERBANKAN

Tidak Ada Tarikan Otomatis Mutasi Rekening Bank / Payment Gateway

Sistem tidak membaca otomatis mutasi rekening koran bank (seperti API BCA/Mandiri) dan tidak menggunakan gerbang pembayaran otomatis (*Payment Gateway* seperti Midtrans). Verifikasi transfer masuk pada Tahap 14 tetap menuntut verifikasi manual oleh petugas Keuangan dengan meneliti file bukti transfer yang diunggah.

Tanpa Tarikan Mutasi Bank Otomatis Bukan Payment Gateway Verifikasi Bukti Transfer Manual
⚙ TATA KELOLA ARSITEKTUR INFRASTRUKTUR SERVER

Menggunakan Polling Berkala, Bukan Server WebSocket Terbuka

Untuk menjaga kestabilan memori server VPS dan menghindari biaya pemeliharaan soket pihak ketiga (Pusher/Soketi), sistem menggunakan sinkronisasi HTTP ringan berdurasi 8 detik. Mekanisme ini otomatis berhenti ketika pengguna sedang mengunggah file demi mencegah tabrakan data.

Polling Ringan 8 Detik Hemat Konsumsi RAM Server Proteksi Anti Tabrakan Data
⚙ TATA KELOLA ARSITEKTUR KEPEMILIKAN DATA

Instalasi Khusus Perusahaan Tunggal (Bukan Multi-Tenant SaaS)

Platform didesain dan diinstal khusus untuk satu entitas operasional internal perusahaan PJK3. Sistem tidak dirancang untuk menjual langganan publik berbasis subdomain (*multi-tenant*), sehingga integritas database tetap privat, cepat, dan terisolasi secara aman.

Khusus Perusahaan Tunggal Bukan SaaS Publik Komersial Keamanan Database Privat
